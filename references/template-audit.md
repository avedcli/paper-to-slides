# 模板审查规范（阶段 0 的判据与报告结构）

当用户拿来一份 `.pptx` 问"这个模板能不能用 / 有什么风险"时，按本文件执行。
工具：`scripts/inspect_template.py <template.pptx> -o template_profile.json`。
**结论必须来自机器实测（解包 OOXML、读属性、换算数值），不能靠观感或版式名字猜。**

## 一、单位换算（全程用得上）

| 场景 | 换算 |
|---|---|
| OOXML 长度 | 1 in = 914400 EMU；1 pt = 12700 EMU |
| 字号 | `a:defRPr/@sz` 单位为 1/100 pt（`sz="2600"` = 26pt） |
| 设计稿 px ↔ pt | 96dpi 下 `pt = px × 0.75`（25px = 18.75pt，16px = 12pt，15px = 11.25pt） |
| 内容文字档位 | 本 skill 用 4 档：**26 / 22 / 20 / 14 pt（14pt 为下限）**，见 `typography-spec.md` |
| px ↔ in | `in = px / 96`（56px = 0.583in） |

## 二、判据表

| 项 | 读什么 | 合格 | 不合格信号 |
|---|---|---|---|
| 页面尺寸 | `presentation.xml/p:sldSz` | 与设计画布严格 1:1（如 12192000×6858000 = 13.333×7.5in = 1280×720@96dpi） | 比例不符 |
| **版式真实性** | `design_signals` / `custom_design` | `userDrawn="1"`，或版式里有手绘形状 / 版式级几何 / 版式级文本样式覆盖 | `custom_design=false`：版式里没有任何自己的东西，子页只能继承 Office 默认值 |
| 页型齐备 | 各版式 `kind_guess` | 至少有 **封面 / 内容页（带标题占位符）/ 分节页 / 纯图页** 四类 | 缺分节页 → Results 无法按大问题分节 |
| 占位符字号 | `#placeholder.size_pt_override`、`inherited_size_risks` | 每个承载文字的占位符都有自己的字号 | 无自带字号 → 继承母版默认（Office 原生 44pt title / 32pt body），常比设计大 2 倍以上 |
| **框高 vs 行高** | `inherited_size_risks[].overflow_by_in` | 框高 ≥ 继承字号 × 1.2 / 72 | 溢出 > 0 → 文字跑出框、与相邻框压叠 |
| 文本锚点 | 占位符 `bodyPr/@anchor`，无则看母版对应 style | 与设计构图一致 | 母版 `titleStyle` 无 `bodyPr` 时锚点回落为 **top**，大标题框会让文字浮到版面上方，与"垂直居中"的设计差上百 px |
| 页眉页脚开关 | `master_hf` | 需要的项为 `"1"` | `<p:hf sldNum="0"/>` 而版式里有页码占位符 → **页码域建了但不会渲染** |
| 颜色落地方式 | `scheme_refs` | 写 `srgbClr` 字面色，或主题色板已改成项目色 | 用 `schemeClr accentN` → 文件里看不到颜色，实渲染取主题值，可能 ≠ 设计主色 |
| 字体一致性 | 主题 `major/minor latin+ea` vs 各版式 `fonts` | 三份 `theme*.xml` 都是 **Calibri + 黑体**且 major/minor 一致；`latin` 槽不得是 `+mj-ea`/`+mn-ea` | 版式硬写 `Inter` 等非系统字体 → 别人机器静默回退、换行错位；三套字体并存；只改 theme1 而 theme2/theme3 仍是 `等线`；`latin` 槽指东亚槽 → 英文按黑体渲染 |
| 对比度 | 设计各前景色 vs 实际底色 | 正文 ≥ 4.5:1 | `#94A3B8` 白底仅 2.56:1、`#A6BEDA` 仅 1.91:1 → 投影看不清 |
| 母版装饰 | `master_decorations` / 版式 `decorations` | 无大块装饰侵占内容区 | 装饰 `area_pct ≥ 20%` 且有重叠 → 可用图区要收窄 |
| 残留物 | `sample_slides_detail` | 无示例页、`max_descr_len` 正常 | 空壳页（`with_text=0`）、`@descr` 内嵌源码、硬编码 `NN / NN` 页码 |
| 可用图形区 | 版式几何推算 | 能容纳**本 deck 实际需要**的子图（含每图图题预留 0.30–0.53 in）；张数由证据决定，**没有固定配额** | 见下 |

### 可用图形区怎么推

```
图区上边界 = 标题带下沿 / 副标题带下沿（取更低者）+ 0.15in 间隙
图区下边界 = 页码带 / 页脚带上沿 − 0.10in；若留图注带再减 0.30in
图区左右   = 页宽 − 左右边距
```
每页 2×2 子图大约需要 `图区高 ≥ 4.5in`。低于 4.0in 时应提示用户"内容页要拆页"。

## 三、报告结构（照此写，便于逐版对比）

```
# <文件> 模板可用性审查报告

- 审查对象（含体积、mtime、core.xml 的 modified 与 Application）
- 审查基准 / 方法 / 日期

〇、更正声明（仅当推翻此前结论时写，写清错因与正确判据）
一、结论速览       —— 表格：维度 | 判定 | 依据（每行都要有实测证据）
二、逐版式实测数据 —— 每个元素的 x,y / w×h（in 与 px 双列）/ 字号 / 颜色 / 锚点
三、与设计稿的逐项换算 —— 设计 px → pt 后逐项对照，标 ✅/✗ 与偏差幅度
四、风险清单       —— 🔴 P0 模板层缺失 / 🟠 P1 影响成品 / 🟡 P2 卫生，每条带量化证据与改法
                      （⚠ 这里的 P0/P1/P2 是**模板风险等级**，与 `SKILL.md` 开头
                      「每一页的四步决策顺序」里讲分页顺序的 P0/P1/P2 无关，勿混用）
五、可用图形区     —— 直接给 plan_layout.py 能用的数字
六、技能侧修正     —— 本次暴露的工具缺陷与修复（若有）
七、下一步         —— 用户在 PowerPoint 里改 vs 由 agent 直接改 OOXML，二选一
附录 复核命令
```

## 四、判读陷阱（都踩过）

1. **占位符里的提示文字不是判据**。`单击此处编辑母版标题样式` / `Click to edit master title style` 是占位符在母版视图下的正常提示语，**任何自制模板都保留它**。用它判"Office 自带版式"会误杀真版式。只看 `design_signals`。
2. **字号要用树查，不能用正则查序列化字符串**。`ET.tostring()` 会写成 `<ns0:defRPr>`，正则 `'<a:defRPr'` 永远匹配不到 → 会漏读全部版式级字号（并连带让溢出检查失效）。
3. **版式齐备 ≠ 模板可用**，**有内容页 ≠ 设计进了文件**。必须同时看版式层和幻灯片层。
4. **模板不需要预置"多子图格位"**。子图由生成阶段按英寸坐标绝对定位，版式里画几个图片框无关紧要；决定每页能放几张图的是**可用图形区尺寸**。别把"每页只有 1 个图片框"当成缺陷。
5. **内容页必须带标题占位符**（Results 页标题 = 科学问题）。只有页码占位符的"空白页"只能当纯图页。
6. **Windows 上解包路径要用 posixpath 归一化**。rels 里的 target 含 `../`，`pathlib` 不做词法归一化 → 版式会读成 0 个。
7. **`<p:hf>` 四个开关容易被忽略**。占位符在文件里躺着不等于会显示。
8. **HTML→PPTX 类导出器有掉页史**。若 `core.xml` 的 `Application` 变成 `Microsoft Office PowerPoint` 而页数变少，先查是不是"经 PowerPoint 另存后掉页"，并要求导出后立即校验页数。

## 五、审查完必须回填的两件事

1. 把实测的模板坐标系写进计划：`title_band_in` / `caption_band_in` / `slide_w_in` / `slide_h_in` → 交给 `scripts/plan_layout.py`。
2. 若模板有 P0/P1 未修项，**在进入大纲阶段前先与用户确认**：要么回模板修，要么明确"由生成阶段显式设定字号/颜色来补偿"（此时生成器不能依赖版式继承）。
