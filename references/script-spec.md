# Script Specification — 配套讲稿规范

讲稿是独立交付物，有自己的验收标准：**总时长**与**解释力**。
它不是"把 PPT 上的字念一遍"，而是把页面上压缩掉的推理链补回来。

> **档位**：**是否产出讲稿本身属 C 档**（用户要求时才做，`SKILL.md` 4.6）；
> 一旦产出，本文档的逐页五要素、时长 90–100%、答疑清单属 **B 档（默认建议）**，
> §8 动笔前核对 deck 版本、§9 逐页核对画面属 **A 档**（照着旧版写讲稿是硬错误）。
> 冲突裁决见 `SKILL.md` 开头「规则优先级总表」。

> 一句话区分：PPT 写的是**结论**，讲稿讲的是**为什么这个结论站得住**。

---

## 1. 讲稿的定位

| 不要写成 | 要写成 |
|---|---|
| bullet 的口语版（"第一点是…第二点是…"） | 每页在整篇论证里的**作用**，以及**为什么下一步必需** |
| 只报结果方向 | 方向 + 量级 + 统计 + 这个量级意味着什么 |
| 逐个面板念图注 | 读图顺序（先看哪个面板、比什么、注意哪条差异） |
| 对作者的复述 | 作者的推断在哪一步、你信到哪一步（与 `claims.md` 对齐） |

**事实来源是原文，不是 deck 的 30 词文案。** deck 为词预算丢掉了限定条件
（`in mice`、`at 8 weeks`、`partially`），照它扩写会把结论说过头。

---

## 2. 逐页五要素（缺一不可）

每页讲稿段落里要能找出这五件事，不要求分小标题，但内容必须在：

1. **本页目的** —— 这一页在论证链上负责哪一环。一句，开头就交代
   （"上一页说明 X 存在，这一页要证明它**必需**"）。
2. **读图顺序** —— 先看哪个面板、和谁比、注意哪条差异
   （"先看 a 的最后一列，再横着比对 b 的剂量梯度"）。
3. **关键结果** —— 方向、量级、`n`、统计，**用数字说话**，不要"明显升高"。
4. **推理桥梁** —— 为什么这个结果支持下一步判断；这里要写出"如果结果相反会看到什么"
   （阴性对照的意义就靠这句立住）。
5. **过渡句** —— 为什么接下来必须看下一组实验（"但这只说明相关，要确立因果还需要…"）。

**没有第 4、5 项的讲稿，就是念 PPT。** 这两项是讲稿存在的理由。

### 2.1 核心图额外要求

A 级证据图（见 `figure-and-author.md` 的分级）每页再加两句：

- **这个实验排除了什么**：点名一个替代解释 + 哪条数据排除的；
- **它没排除什么**：留到 Limitations 或下一张图解决。

---

## 3. 答疑清单（核心图各一份）

正式 PPT 里不放，作为准备材料。每题给**答案要点 + 出处**，不写完整台词。

| 问题 | 要点 |
|---|---|
| 关键阴性对照够不够？ | 它排除了哪种伪影；若不够，缺什么 |
| `n` 与统计是否合理？ | 生物学重复数、检验方法、是否校正多重比较 |
| 是否存在替代机制？ | `claims.md` 里未排除的那几条 |
| 如果只能补一个实验，做什么？ | 写 `claims.md` 的 Decisive experiment |
| 结论能否外推到其他细胞/模型/疾病？ | 边界在哪（小鼠→人、急性→慢性） |

问题按**最可能被问到**排序，通常前三题是：对照、样本量、可否外推。

---

## 4. 时长换算

**不要用"汉字数 ÷ 200"**——英文术语占比高的稿子会被严重低估。

- 语速基线：中文正式汇报 **≈ 230 音节/分钟**。
- 音节数 = **CJK 字符数 + 英文 token 音节数**。英文 token 估法：
  - 全大写缩写按字母数展开（`CASP`=4、`PDB`=3、`PAE`=3）；
  - 含数字的 token 记 3（`AlphaFold2`、`HIV-1`）；
  - 普通英文词取 `max(2, round(len/3))`（`AlphaFold`=3、`hexokinase`=3）。
- 算式：`分钟 = 音节数 / 230 + 看图停顿（0.5–1 min）`。
- 校准例：4100 汉字 + 250 英文音节 = 4354 音节 → 18.9 min @230。

另有按"字词数"换算的简化口径，与音节模型实测相差 <5%——缩写密集的稿子用音节模型更准。

**逐页时长必须逐页实测换算**，不能凭感觉分配：按页统音节 → 四舍五入到 5 秒 → 算累计列。
密度基准：≈150 字/页、≈45 秒/页；分节页 50–70 字（12–20 秒），局限页可到 360 字（1:40）。
实测教训：凭感觉给某页 2:20、换算实为 2:54（差 34 秒），这类页就是台上会跑偏的地方。
首稿最长的页通常**不在 Results**，而在最不设防的"局限与展望"。

**总时长目标落在时限的 90–100%**：超时是事故，明显过短（<70%）同样是准备不足。
富余时补拓展页（争议、不足、后续方向、成药可行性），**不靠放慢语速或重复结论**凑时间。

---

## 5. 讲稿骨架（七节）

1. **使用说明**：语速口径 + 全文口播量 + 总时长；
2. **时间轴总览表** + **2 个硬锚点**（"讲完第 N 页应在 X 分 Y 秒"）+ 指定**一页作可压缩缓冲页**；
3. **逐页讲稿**：每页 `> 【时长 累计】` + 口播正文用**连续段落**写（不要用项目符号，
   照着列表念会变成念稿）+ `> 台上提示`（指向哪张图、哪里停顿、时间紧时省哪句）；
4. **收尾**：用户要求"无总结页"时，**口头收尾仍然必需**——标"停留在最后一页，不换页"，
   不要新增页面；
5. **术语与读音对照表**（含缩写怎么念）；
6. **预设问答 5–6 条**（用原文口径回答，见 §3）；
7. **时长调节**：压到 X 分钟删哪些、扩到 Y 分钟加哪些——**台上真正会用到的是兜底方案**。

表格里的 ⚠ 标记必须写在最后一格里面（`| … 0:20–1:35 ⚠ |`），写在行尾竖线外面会多出一列、
整张表错位。

---

## 6. 长稿迭代：先干净源稿，再定点删句

首稿一定超时（实测 33 页首稿 29.8 min，两轮定点压缩到 23.9 min）。
**只有删句子能省时间**，不要靠调语速或改换算系数凑数。

目录约定：`work/script_final.md`（纯正文，无任何标注）→ 脚本换算 → `讲稿.md`。
脚本必须**幂等**：先剥掉已有的时钟标注与旧时间轴再重算，否则连跑两次会叠出两层时钟。

定点删句优先顺序（都能删、且不损科学）：

1. 纯过渡句（"接下来看…""这一页问的是…"）；
2. 与后文重复的预告句；
3. 图注已写明的指路句（"Fig Xa 和 Xb 回答第一个问题"）；
4. "也就是说…"复述第二遍的口语句。

**不要删**：数字、图号、以及"为什么这一步是必要的"这类因果句。

---

## 7. 工程注意（实测踩坑）

- 一次改十几处小文本时，**不要发并行 Edit**——同一文件的并行编辑会互相覆盖，
  实测出现"返回成功但没落盘"（表格生效，页眉与 12 处标注全丢）。
  改成**一次脚本原子替换 + 逐个 `count()==1` 校验**，或串行单次编辑。
- 用 bash heredoc 写长 Python 补丁脚本，正文里的引号会把 heredoc 截断——
  **改用 Write 落一个 `work/xxx.py` 再执行**。
- 脚本重写过某文件后，再用 Write 改同一文件会报 `File has been modified since read`——
  **始终写到另一个文件名**，最后一步才生成成品。
- 定点替换前先探一次文件的引号类型（全篇 ASCII `"` 还是中文弯引号），
  否则 `old` 串差一个字符就静默 MISS；补丁脚本要打印 `applied N/M` 并逐条核对。

---

## 8. 动笔前先确认 deck 是哪一版（最关键）

用户常在拿到 deck 后自行精简（实测有 33 页压到 13 页、再压到 11 页的先例，会删掉整个 Part）。

- 用 `Presentation(...)` **只读**遍历，逐页 dump **标题 + 图注 + 图片数量**
  （`.pptx` 被 Office 占用时走这条，不要走本地编辑器通道——实测它返回
  `is_open:false`、`slide_count=0`；只读解析不写入，安全）；
- 与 `outline.md` 做差集，列出**被删掉的页**，并明确每块被删内容改由哪一页**口头承接**
  （模型对比 → 背景页口述；方法策略 → 分节页口述；储备细节 → 口头收尾）。
  **被删的内容不是可以省略的内容，它必须迁移到口播里**，否则结论会突然悬空。

---

## 9. 逐页核对"画面实际是什么"，不要相信图注

用户手工编辑会留下**过时图注**与**被压扁的残留图片**
（实测：主图已换，图注还在讲旧内容；同页压着被压到 0.33 in 高的旧图）。

做法：把每页的 `Picture` 逐个 `Image.open(BytesIO(sh.image.blob))` 导出并**看图确认子图编号**
（a/b/c 字母在图片内部，是唯一可靠的身份标识），再决定口播指向哪些 panel。

判定图片是否被拉伸：比较 `sh.width/sh.height` 与 `image.size` 的宽高比。
组合图形（`GroupShape`）不要自己算坐标渲染——子图形的 `left/top` 是组内坐标系，
直接相加会得到跑到画布外的假结果；只用来判断"有没有多余残留"，位置交给 PowerPoint 里看。

---

## 10. 两级结构交付，天然可伸缩

核心口播写连续段落（照念即可），另标两类可选句：

- **〔加时〕**：时间富余时插入，每条 15–25 秒；
- **〔可省〕**：时间紧时跳过。

开头给"时间校准"块，写清**实测数字**（核心字数 / 可选句字数 / 各档总时长），
并给 2–3 个**中途对表锚点**（"翻到第 N 页应为 X:XX"）。这比写死一个总时长实用得多。

---

## 11. 交付时附"开讲前请先处理的页面问题"

讲稿是最后一道人工校对关口。当 deck 被占用无法直接改时，把发现的问题逐条写进讲稿末尾
并给改法：页码与页序不一致、分节页残留上一节标题、过时图注、压扁残留图、图注标点不统一。
写在文件里比只在对话里说更容易被执行。

---

## 12. 交付说明要交代版本

工作区常同时存在 `deck.pptx`（用户在改）与 `deck_v2.pptx`（助手生成）两个分叉版本。
最终答复必须写明"**你改的是哪个文件、我读的是哪个文件**"，否则用户会以为讲稿对应的是另一份。
