# Layout Specification — 子图排版规范

本文档定义 paper-to-slides 中子图排版的全部规则：大纲中的排版计划如何写、生成时如何确定
坐标、以及何种冲突必须停下交由用户裁决。

> **档位**：本文件里"证据清单不可改"与"不与固定组件重叠"属 **A 档（不可妥协）**；
> 图占比最大化、留白均衡、阅读顺序属 **B 档（默认建议）**；图占比数值与图内文字大小是
> **纯诊断值**，只汇报、不驱动决策。冲突裁决见 `SKILL.md` 开头「规则优先级总表」。

## 一、大纲中的排版计划（Layout 字段）

`outline.md` 中每一张含子图的页面**必须**包含 `Layout:` 字段，写明：

1. **布局模式**（从下方布局目录中选择，如 `2x2`、`1+2 (fig1a big left)`、`bodyL|1+2`）
2. **哪个子图放在哪个位置**，以及为什么（如 "fig2a 全高居左作为关键证据，fig2b/c 居右堆叠作对照"）
3. **相对大小意图**（如 "fig2a 与 fig2b 同图同比例；fig3c 缩小放置"）
4. **当页内容量与内容关系**（自适应选型的依据，一句话即可）：
   - 内容量：面板数 + bullet 词数/条数 → 正文区放哪（是否声明 `body_zone` 及其方位）；
   - 关系：主次（key 是哪张）还是并列 → `structure: hierarchy/parallel` 与 `role: key`。

这保证大纲阶段就完成排版设计，用户确认大纲时即确认了排版意图。

## 二、布局模式目录

⚠ 本节的"面板数"是**第 2 步（证明该问题需要哪些子图）的结果**，不是事前配额。
先写死问题 → 再收证据 → 收到几张就查下表；表只是"几张图怎么摆"的字典。

**选型三输入（每页独立判断，这就是"内容页自适应排版"）**：

| 输入 | 怎么读 | 落到 plan.json |
|---|---|---|
| 面板数 | 第 2 步收到的证据清单长度 | `panels` 列表（原样照抄） |
| 文字量 | bullet 总词数 > 30，或 ≥ 4 条 bullet 且面板 ≤ 3 → 正文放不进底部旧位置，声明正文区 | `body_zone: {pos, in}`（pos = top/bottom/left/right，in = 高或宽，in） |
| 内容关系 | 一张决定性证据 + 其余为配套/对照 → 主次；几张证据地位相等 → 并列 | 主次：`structure: "hierarchy"` + 给那张图 `role: "key"`；并列：`structure: "parallel"` |

**图注带 ≠ 正文区（两个模块，不得混写）**：

| | 图注带（`cap-band`） | 正文区（body zone） |
|---|---|---|
| 承载 | **L4 = 14pt 小字，两类行**：① 名词注释行（首现即写，**每页都可以有**）；② 补充行（瓶颈 / 试剂原理，**默认没有**，判据见 SKILL.md 3.6） | **当页关键正文（L2 = 22pt，次级 L3 = 20pt）**：bullets、模块块（填充底 + 反白） |
| 位置 | **永远页面底部**，由 `caption_band_in` 预留；**一行都没有的页把 `caption_band_in` 设为 0**，图区拿回这段高度 | **自由排版模块**：`body_zone: {pos: top/bottom/left/right, in}` 每页声明；不声明 = 旧行为（正文条紧挨图注带上沿） |
| 输出 | `cap-band` 文本框，y ≥ scaffold_y，不计正文词数 | `layout.json` 的 `body_box: {x,y,w,h}`，生成时照抄，内部按 typography-spec 的层级与模块块规则自由排 |

**固定模块在任何布局下都不可被侵占（A 档）**：标题带、页码、底部 L4 = 14pt 图注带
（`cap-band`，`caption_band_in > 0` 时才存在）、每张子图自己的图题行（`cap-*`）——
脚本是先把这一切预留出来再枚举候选，
所以 `layout.json` 给出的任何坐标（含 `body_box`）都天然不碰它们；生成时照抄坐标即可，
不做手工微调。正文区内部怎么排（bullets 顺序、模块块套底）由生成阶段按 typography-spec 决定，
但正文区整体位置由 `body_zone` 在规划期定死，避免生成时随手把正文贴回图注带。

| 面板数 | 模式 | 适用 |
|--------|------|------|
| 1 | 单图居中，最大化（有正文区且 pos=left/right 时为 `bodyL\|1x1` 图右文左） | 该图**自己有独立科学问题且证据足够决定性**时合法（高分辨率结构、单张决定性成像、完整遗传学证据链），不限宽高比。若它只是某个问题的一部分，才考虑与相邻页合并；<50% 时如实注明，不硬拼 |
| 2 | `1x2-row` / `2x1-col` / `1+1-big-left` / `1+1-big-right` | 并列按两图纵横比选：横向图并排，纵向图上下；主次用 big 变体，key 图占 55% 宽全高 |
| 3 | `1x3-row` / `3x1-col` / `1+2 (big left)` / `2+1 (big right)` / `wide-top+2` / `2+wide-bottom` | 一主两次用 1+2（key 图自动进大格）；一张宽图 + 两张窄图用 wide-top/wide-bottom；并列用等分行/列 |
| 4 | `2x2` / `1x4` / `4x1` / `1+3-big-left` / `3+1-big-right` | 并列默认 2x2；主次用 1+3 |
| >4 | `1x5-row` / `2x3` / `3x2` / `1+4-big-left` 等（脚本枚举全部分解 + 大格变体，按面积择优） | 只有当其中**确有可独立成问的子问题**时才回第 1 步拆页；没有就保留多图证据页。**不要为凑张数砍证据，也不要为凑张数硬拆** |

`bodyT|` / `bodyB|` / `bodyL|` / `bodyR|` 前缀 = 该页声明了正文区（pos = top/bottom/left/right）。
`layout.json` 会给 `body_box` 坐标（bullet/模块块专用，生成时照抄），同一套网格在正文区
让出的剩余图区里照常枚举，所以声明了正文区的页面候选一个不少。
`structure: "hierarchy"` 时正文区常配 `bodyL|`（文左图右：先论点后证据）；
`bodyT|` 则是"标题 → 正文定调 → 图收尾"，适合论证短、图强的页。

选择规则：`plan_layout.py` 会枚举全部候选并按评分自动选取（`structure` 只给 ±4 的确定性
微调，几何差异大时几何仍然获胜），大纲中的布局模式是预期值。
**前提是 plan.json 里 `"min_text_px": 0`**（否则评分会被第 4 步的记录值带偏，见第四、五节）；
传 0 之后脚本只在"这一页已有的这几张图"里找不重叠、图占比最高、留白最匀的排法，
所以它给出的结果**永远在同一页之内，不会改变分组**——脚本与预期冲突时以脚本结果为准，
在交付说明里提一句即可，不必回头改大纲。

## 三、排版规则（生成 PPTX 时逐条满足；按档位与序号裁决，序号小的优先）

**缩放规则只有一条**：每张子图缩放到**不重叠约束下允许的最大尺寸**，到此为止
（`scale = min(格子宽/图宽, 格子高/图高)`）。没有任何"留给文字变大"的余量可花。

**规则之间冲突时，序号小的优先，不得颠倒。**

0. **证据清单不可改（A 档，不可妥协，且在第 1–2 步就已定死）**：这一页放哪些子图，取决于"它们是否
   在为第 1 步的问题提供**必要或配套**证据"。排版阶段**只能接受这份清单**——不得为把图占比做高
   而把不相干的子图挪进来，也不得为了让某张图变大而把必需的图挪走。
   布局确实放不下时的唯一合法动作是**回第 1–2 步重新分组**。合法触发点只有三类：
   ① 这一页其实是两个问题；② 其中确有可独立成问的子问题；③ 阶段 2 发现证据链断。
   **图占比不够、图内文字偏小、图数超过 4 张都不是触发点**——图数是证据必要性的结果，
   不是配额。回退要记进大纲的「修订记录」（写明属于①②③哪一类）。
1. **无遮挡**：标题带（顶部）、图注/要点带（底部）、子图内容区三者互不侵占；子图间最小间距 ≥ 0.12 in。所有摆放坐标由 `plan_layout.py` 输出，不做手工微调到重叠区。
2. **同图等比**：来自同一张原图的子图（同 `group`）必须以相同缩放比例渲染，保持原图中的相对大小关系。
3. **图面积最大化**（目标）与 **50% 参考线**（诊断指标，不是门槛）：图面积 / **可用图区面积**；可用图区 =
   内容区扣除标题带、图注带与页边距后的净面积，不是整页面积。**先把面积做到布局允许的最大值**——
   这就是 `plan_layout.py` 在 `min_text_px: 0` 下的择优目标（枚举边距 / 图注带 / `1x3` ↔ `1+2` / `2x2`
   并取面板总面积最大者）。
   **50% 不是及格线，低于它不阻塞交付**：只要这一页的证据都是必需的、排布已取到布局最大值、
   关键证据可读，就照常交付并在交付说明注明数值与原因（高瘦图 / 近方形图 / 必需的图确实多）。
   取到最大仍 < 50% 时**只做一步判断**：**① 这一页有没有"相关但非必需"的图？** 有 → 移走重排；
   没有 → **② 接受并注明**。**绝不**靠缩小图、删必需的图、缩小文字、塞不相干的图来凑数字。
   脚本之外，人工还可做三件事把面积推得更高：
   a. **加大图区**——内容左右边距收到版式 `figure_area` 的 x（内置母板 0.44–0.55 in 而非 0.917 in），
   图形带起点从 y ≈ 1.20 起（标题占位符底边 1.085 之下）；
   b. **缩短图注带**——图注压到 y ≈ 6.94 一行即可（见 `typography-spec.md` 的 L4 档）；
   c. **裁掉子图自带白边**（见下"四、排版流程"第 1 步）。
4. **留白均衡**：内容区利用率过低或单图独大都要修正。
5. **阅读顺序**：子图顺序 = 论证顺序（左→右、上→下），与页面要点顺序一致。
6. **对齐**：同排子图垂直中线对齐、同列水平中线对齐（脚本居中摆放天然满足）。

> 注：曾经存在过的"跨子图文字大小差异超过 3 倍视为比例失衡"判据**已作废**——
> 那会把第 4 步的图内文字重新拉回决策链。同组子图本来就可能带不同原始字号，
> 只要同图等比（第 2 条）成立即可。

### 子图标签与图题（每张上页子图必配）

**每张上页的子图，正下方必须有一行「子图编号 + 一句话图题」**，形如
`Fig. 5a  IL-13 suffices to expand Tuft cells`。没有这一行，听众看完图不知道该把这图当成什么证据。

**图和图题是一个整体，不是"图 + 页面底部的一行字"**：

| 项 | 取值 |
|---|---|
| 位置 | 紧贴该子图**下沿**，gap **0.06 in**；宽度 = 该子图宽度；左对齐 |
| 行数 | **1 行**为默认，**最多 2 行**；需要第 3 行说明标题写太长——删到 ≤ 8 词 |
| 高度 | 1 行 ≈ **0.30 in**（14pt × 1.22 = 0.237 in + 0.06 gap）；2 行 ≈ **0.53 in** |
| 字号/颜色 | L4 = **14pt**，次要灰 `#64748B`；`Fig. 5a` 那一小段**加粗**（同字号同色，不另起一档） |
| 命名 | `cap-<label>`（如 `cap-fig5a`） |

**在 plan.json 里预留，不要事后硬塞**：设 `"panel_caption_in": 0.30`（两行写 `0.53`），
或给每个 panel 写 `"caption_lines": 2` 让脚本按最长的一条推算。脚本会把每个格子的
**可放图高度扣掉这段预留**（`格子高 − panel_caption_in`），并把图**贴底对齐**，
因此同一行的图题基线一致；输出里每个 placement 会带 `cap_x / cap_y / cap_w / cap_h`，
生成时直接照抄这四个值，不要再自己算。`panel_caption_in = 0`（缺省）时行为与旧版完全一致。

⚠ **预留会让 `figure_coverage` 略降，这是正常的**：图占比只统计**图面积**，图题不计入分母。
图题挤掉的那点图面积换来的是"每张图都有身份"，优先级更高（B 档 vs 诊断值）。
**不得**为了保住图占比数字而省掉图题，也不得为省图题而把图缩小后再补。

**图题写什么**（这是科学的活，不是排版的活）：

- 写**这一张子图直接展示了什么**（观察句式）：`Fig. 5b  KLRG1+ ILC2s expand 5-fold after IMQ`；
- **不写本页结论**——结论由 bullet 和页面标题承担，重复一遍只是占版面、还容易越级；
- **不写作者未做的推断**，也不把相邻子图的结论并进来（那是 claims.md 的事）；
- 图上已经画清的处理流程、时间轴、分组名，图题里不再念一遍；
- ≤ **12 词**；一页图题合计 ≤ **40 词**，超过它说明你在写第二套正文。

**与页面底部图注带的分工**（不重复；前者必写，后者看行类）：

| 位置 | 承载 | 谁承担 |
|---|---|---|
| 子图正下方（`cap-*`） | **这张图是什么**：编号 + 一句观察 | 每张图各一条，**必写** |
| 页面底部图注带（`y ≥ scaffold_y`，命名 **`cap-band`**） | **这页里的词和图，读之前要先知道什么**：① 名词注释行（首现即写，每页都可以有）② 补充行（瓶颈 / 试剂原理，默认没有） | ① 按"本页有没有首现名词"决定，**不设频率上限**；② 只在"不写会让听众读错图或判高结论"时才写，**带补充行的页应少于 1/3** |

两者都不计入正文 30 词预算（属 L4 图注），区别是前者逐图、后者逐页。

**`caption_band_in` 按实际行数给**（14pt 单行 = 0.237 in，上下留白 0.18 in）：

| 图注带行数 | `caption_band_in` | 典型构成 |
|---|---|---|
| **0 行** | **0.00** | 本页没有首现名词、也没写补充行（背景页 / Intro 已建立过这些词） |
| 1 行 | **0.42** | **常见形态**：只有一行名词注释 |
| 2 行 | **0.66** | 名词注释 + 一条补充行（瓶颈或试剂原理） |
| 3 行 | **0.90** | 名词注释 + 两条补充行；超过 3 行改开背景页或拆页 |

留 `0.42` 默认值却写两行是本 skill 的高频溢出源：PowerPoint 不裁剪溢出文本，第二行会直接压到
图或页脚上，而 `plan_layout.py` 的图区计算是按预留值倒推的，看不出这个问题——
**行数在规划阶段就要定死，不要等导出后再补**。

⚠ **底部图注带也必须按 `cap-` 命名（`cap-band`），这不是可选的**：`verify_deck.py` 的层级检查
要挑一个"正文块"作参照，挑的是**词数最多（≥6 词）的非图注文本框**。图注带天然词数最多，
若它不叫 `cap-*`，就会被当成正文块——而它是 L4 末档，任何短标签都不可能"更低一级"，
于是**倒挂检查整体失效、真倒挂被漏报**（实测：同一页不命名时不报，命名后正确报出
"ShortLabel 14pt 小于正文块 BodyBullet 20pt"）。



**`group` 只给"同一张原图里尺寸不同的子图"用**（第 2 条）。若一页的几个子图本来就同尺寸，
强行同组会在 `1+2` / `2+1` 这类格子不等大的布局里把大格子拖到与小格子同比例，
图占比直接腰斩——这类页面应当**不设 group**。实测：3 张方形图 `1x3-row` 给 69.4%，
设了 group 的 `1+2` 反而只有 45%。

### 高瘦子图的特别处理

**2–3 张高瘦子图（宽高比 < 0.5，如整装 X-GAL）单独成页很难到 50%**：面积上限 =
图区高 × 图区高 × 宽高比，一页放两张也只有 ~36%。**这是几何事实，不是缺陷**，
只要这些图都是必需证据，就接受并在交付说明注明，不必再折腾。

改善排布（仍属同一小问题才算合法）：**一张高瘦图 + 一两张宽图同页**（宽图把横向剩余空间吃掉），
或让高瘦图与该组其他宽图占满整行。**配对对象必须仍属同一小问题**——跨小问题硬配对违反第 0 条，
应当改为"该高瘦图单独成页 + 在交付说明中注明图占比偏低"。不要硬压其他页。

### 方形子图的特别处理

**近方形子图在 16:9 页面上凑图占比，优先减少每页张数，不要靠缩图或塞图**
（`verify_deck` 分母 74.90 in² 时）。这是**经验数据，用于把面积做大的选型参考**；
选完仍低于 50% 的，按诊断指标处理——接受并注明，不回头动证据清单：

- 4 张近方形图：`1x4-row` 是上限——`margin_in=0.34 / gap_in=0.08` 时 4 张各 3.103 in，
  合计 **51.4%**；改 `2x2` 掉到 ~40%（若这 4 张都是必需证据，接受并注明，不要拆走一张）。
  想让面积更好看，2 张一页可到 60–88%——但**只有当这确实是两页各自的独立问题时才可拆**。
- 3 张方形图：`1x3-row` 给 69.4%，`1+2` 只有 45%（见上"group 适用范围"）。
- 反之，**方形画布本身是好选择**：结构渲染、单分子示意图都渲成 1:1（结构居中、四周留白），
  整页观感统一、面积也算得准，比按紧边界裁成长方形再拼行更好排。

### 两个 figure_coverage 分母不一致（规划时必须留余量）

`plan_layout.py` 的 `figure_coverage` 分母 = 传入的 content area（**已扣图注带**）；
而阶段 5 `verify_deck.py` 用的是**模板版式自带的 `figure_area`**
（如内置母板 12.453 × 6.015 = **74.90 in²**，**不扣图注带**）。
同一页在前者可能显示 58%，到后者只有 53%——**两个读数不同，仅此而已**。

**做法**：规划阶段就把 verify 的分母写进择优逻辑
（`share = 子图面积和 / (版式 figure_area 宽 × 高)`，内置母板即 `面板面积和 / 74.90`），
并在候选里挑面积最大的那个，而不是事后补救。
⚠ 两个分母不一致只影响**读数**，不影响交付——按 verify 的口径算，是为了避免"规划 58%、
实际 53%"这种误判；**低于参考线的页不再阻塞**（见五 5.2）。

### 文字大小：只记录（仅当关键证据不可读时才复核，见五 5.1）

子图内最小文字渲染到幻灯片上的显示尺寸，换算为
**显示文字 px = 源图文字 px × 缩放比 × 96**。舒适线取 **14pt（≈18.7px）**——与内容文字末档
（L4，见 `typography-spec.md`）同一个值，便于判断"图里的字会不会比图注还小"。

**这个数只是一个记录值，不是约束、不是阻塞条件、不触发上报，也不参与任何决策。**
因为缩放已经取到"不重叠"允许的最大值，文字大小是结果而非可调项——
没有任何决策空间可以交给用户。脚本会把它打印出来（`text_display_px`）+ 一行说明，
**用来说明你在交付什么，而不是提示你该去改什么**。

⚠ **它绝不构成拆页或挪图的理由。** 那属于用第 4 步反向改写第 1–2 步：一页字小，恰恰说明
"这个问题确实需要这么多条证据"，是诚实呈现而非缺陷。若你判断某页确实需要更好的可读性，
那本质上是**第 1 步"这个问题该不该拆成两句"**的判断——回第 1 步重议。
**不要为了它停下来问用户。**

## 四、排版流程（生成阶段）

1. 查看每个裁剪好的子图，**估算源图中最小有意义的文字高度（px）**——这是文字大小检查的输入，估算时以图内坐标轴刻度/图例等需要被读者看清的最小文字为准。
2. 为每张幻灯片写 `plan.json`（schema 见 `plan_layout.py` 头部注释）：子图清单（label/file/text_px/group/**role**/caption_lines）+ 版面参数（从模板读取页面尺寸与标题/图注带高度），
   **并给出 `panel_caption_in`**（每图下方图题的预留高度，见上"子图标签与图题"；不用图题才省略，默认 0）；
   再按本页的内容量与内容关系给自适应输入：正文重就写 `body_zone: {pos, in}`（输出会带
   `body_box`；图注带 = 14pt `cap-band`，永远在底部，与正文区是两个模块，见上表），
   主次结构写 `structure: "hierarchy"` + 关键图 `role: "key"`，并列结构写 `structure: "parallel"`。
   **一页的 `panels` 列表 = 第 2 步"证明该问题需要的子图"清单，原样照抄，不得增删。**
   这一步只是把已经定好的证据清单写下来，不是重新编组、也不是补图凑面积。
3. 运行 `python plan_layout.py plan.json -o layout.json`，得到每页精确摆放坐标（英寸）与告警。
   ⚠ plan.json 里**一律写 `"min_text_px": 0`**：脚本默认给每张低于舒适线的子图扣 40 分，而覆盖率不足只扣 15 分，
   会让第 4 步的记录值压过第 3 步的目标函数（实测把图占比 80% 的 `1x3-row` 判给了图占比 59% 的 `1+2`）。
   传 0 后脚本只优化"不重叠 + 图占比最大 + 留白"；图内文字大小按第 1 步的实测值照常打印、照常汇报。
4. 按 `layout.json` 的坐标在 PPTX 中摆放子图；每张图**照抄它自己的 `cap_x/cap_y/cap_w/cap_h`**
   放一行 `Fig. 5a  <一句话图题>`（命名 `cap-fig5a`）。同页共用的瓶颈行（SKILL.md 3.6 三问选定）
   仍写入页面底部图注带——两者分工见上"子图标签与图题"。

## 五、异常处理

### 5.1 图内文字偏小 —— 先判是不是"关键证据不可读"

**多数情况它不是缺陷**：缩放已取到"不重叠"允许的最大值，字小只是数学结果，记录后照常交付。
但有一种情况必须处理：**决定结论的那部分读不出来**——剂量梯度、组别标签、显著性标记、
坐标轴刻度。这时听众无法核验结论，字号就从"记录值"变成了"证据完整性问题"。

判据（先看图再判断，不要只看数字）：

| 情形 | 处理 |
|---|---|
| 小字是图例、注释、非关键刻度 | 记录 `text_display_px`，照常交付，交付说明里报一句 |
| 小字是**关键证据**（剂量、组别、统计标记、决定结论的标签） | 触发一次**可读性复核**，按下面顺序，不得跳级 |

可读性复核的顺序（**不得**直接缩小正文或删文字来腾空间）：

1. **换布局**：在证据清单不变的前提下，让关键子图拿更大的格子（`1+2` 让主图全高、
   `2x2` 改 `1x4` 等），重跑 `plan_layout.py`；
2. **裁掉多余白边 / 去掉非关键面板的留白**（不改变证据清单）；
3. **回第 1–2 步**：若确实拆不开也放不大，说明这一页承担的证据过多，按回退规则②处理
   （拆页或把次要证据标 `outline-only`），并记录修订原因；
4. 仍不可读 → **如实写进交付说明**：哪张图、哪部分读不清、建议现场用原图放大或口头说明。

⚠ 不要为了字大而拆页，也不要为了字小而砍证据。**先问"这部分是不是关键证据"，再决定动不动。**

### 5.2 真正需要停下来排查的情况

仅当出现下列**硬失败**时才停止该页处理。**图占比偏低不在其中**——它是诊断指标，
取到布局最大值后仍低于参考线就接受并注明（见下表最后一行）。

| 情况 | 判据 | 处理 |
|------|------|------|
| 子图放不进任何候选格位 | `layout.json` 的 `ok: false` + `error` 字段 | 检查 `plan.json` 的 `margin_in` / 带宽 / 页面尺寸是否与模板一致；参数修好后重跑 |
| 一页子图很多（脚本打 `[NOTE] n panels`） | 仅提示，不是告警 | **不是硬失败**。图数是证据必要性的结果：同一问题、拿掉任一张结论就悬空的，全部保留（选 `1x5` / `2x3`）；只有当其中确有可独立成问的子问题时才拆页。**不要砍证据** |
| 图占比取到最大后仍 < 50% | `figure_coverage` | **不是硬失败**。只查一次"有没有相关但非必需的图"：有 → 移走重排；没有 → 接受并在交付说明注明数值与原因，继续生成（脚本侧已改为 warn-only，不再进退出码；`--figure-blocking` 可恢复阻塞，`--figure-pct-override "12=42"` 可声明该页接受值） |
| 规划与 verify 的图占比读数对不上 | `verify_deck` 的 `WARN` 数值 < `layout.json` 的 `figure_coverage` | 两个 `figure_coverage` 分母不一致（见三）。**读数差异不构成失败**，脚本图占比早已不进退出码；如需核对，按 verify 的分母自算 |

处理完即可继续生成，只有**参数本身与模板不符**这类情况才需要向用户确认。
